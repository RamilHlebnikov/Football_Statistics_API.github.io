1. Football Statistics API - проект на REST API для работы с футбольной базой данных (продолжение 5-го задания по Системной Аналитике)



API предназначен для хранения и получения информации о футбольных лигах, игроках, командах и статистике игроков.



Проект основан на базе данных PostgreSQL (5-ое задание по Системной Аналитике), которая содержит основные таблицы:

1. leagues - лиги;
2. teams - команды;
3. players - игроки;
4. player\_stats - статистика игроков (голы + передачи).



API позволяет выполнять стандартные операции CRUD (создание, чтение, обновление, удаление) с основными ресурсами, а также получать аналитические данные: общее количество голов, топ бомбардиров, статистику команд и классификацию игроков по результативности.



2. Для проектирования API выбран подход REST API, потому что он простой и понятный и сразу понятно что он работает с ресурсами и использует HTTP-методы:
3. GET - получение данных;
4. POST - создание (добавление) новой записи;
5. PUT - полное обновление данных;
6. PATCH - частичное обновление данных;
7. DELETE - удаление записи.



Данные в запросах передаются в формате JSON, пути по умолчанию:

API:

http

/api/v1



endpoints:

GET /api/v1/statistics/top-scorers?limit=5



3\. Ключевые ресурсы

league — лига

Ресурс league хранит информацию о футбольной лиге или чемпионате.

Поля:

1. "leagueId" — уникальный идентификатор лиги;
2. "leagueName" — название лиги;
3. "country" — страна или регион проведения.



Пример объекта:



json

{

&#x20; "leagueId": 1,

&#x20; "leagueName": "Saudi Pro League",

&#x20; "country": "Saudi Arabia"

}

team — команда

Ресурс team хранит информацию о футбольной команде и её турнирной статистике.

Поля:

1. "teamId" — уникальный идентификатор команды;
2. "teamName" — название команды;
3. "leagueId" — идентификатор лиги, в которой играет команда;
4. "matchesPlayed" — количество сыгранных матчей;
5. "goalsFor" — количество забитых голов;
6. "goalsAgainst" — количество пропущенных голов;
7. "points" — количество очков.



Пример объекта:

json

{

&#x20; "teamId": 1,

&#x20; "teamName": "Аль-Наср",

&#x20; "leagueId": 1,

&#x20; "matchesPlayed": 30,

&#x20; "goalsFor": 81,

&#x20; "goalsAgainst": 21,

&#x20; "points": 79

}



player — игрок

Ресурс player хранит информацию о футболисте.

Поля:

1. "playerId" — уникальный идентификатор игрока;
2. "playerName" — имя игрока;
3. "nationality" — национальность игрока;
4. "teamId" — идентификатор команды игрока.



Пример объекта:

json

{

&#x20; "playerId": 1,

&#x20; "playerName": "Криштиану Роналду",

&#x20; "nationality": "Португалия",

&#x20; "teamId": 1

}



PlayerStat — статистика игрока

Ресурс PlayerStat хранит статистику игрока по голам и голевым передачам.

Поля:

1. statId — уникальный идентификатор записи статистики;
2. playerId — идентификатор игрока;
3. goals — количество голов;
4. assists — количество голевых передач.



Пример объекта:

json

{

&#x20; "statId": 1,

&#x20; "playerId": 1,

&#x20; "goals": 25,

&#x20; "assists": 2

}



4. endpoints и HTTP-методы:

Игроки

1. GET /api/v1/players — получить список всех игроков;

2\. GET /api/v1/players/{id} — получить игрока по ID;

3\. POST /api/v1/players — создать нового игрока;

4\. PATCH /api/v1/players/{id} — обновить данные игрока;

5\. DELETE /api/v1/players/{id} — удалить игрока.



Пример ресурса Player:

{

&#x20; "playerId": 1,

&#x20; "playerName": "Криштиану Роналду",

&#x20; "nationality": "Португалия",

&#x20; "teamId": 1

}



Лиги

1. GET /api/v1/leagues — получить список всех лиг;
2. GET /api/v1/leagues/{id} — получить лигу по ID;
3. POST /api/v1/leagues — создать новую лигу;
4. PATCH /api/v1/leagues/{id} — обновить данные лиги;
5. DELETE /api/v1/leagues/{id} — удалить лигу.



Пример ресурса league:

{

&#x20; "leagueId": 1,

&#x20; "leagueName": "Saudi Pro League",

&#x20; "country": "Saudi Arabia"

}



Команды

1. GET /api/v1/teams — получить список всех команд;

2\. GET /api/v1/teams/{id} — получить команду по ID;

3\. GET /api/v1/leagues/{id}/teams — получить команды конкретной лиги;

4\. POST /api/v1/teams — создать новую команду;

5\. PATCH /api/v1/teams/{id} — обновить данные команды;

6\. DELETE /api/v1/teams/{id} — удалить команду.



Пример ресурса teams:

{

&#x20; "teamId": 1,

&#x20; "teamName": "Аль-Наср",

&#x20; "leagueId": 1,

&#x20; "matchesPlayed": 30,

&#x20; "goalsFor": 81,

&#x20; "goalsAgainst": 21,

&#x20; "points": 79

}



Статистика игроков

GET /api/v1/player-stats — получить статистику всех игроков;

GET /api/v1/player-stats/{id} — получить запись статистики по ID;

GET /api/v1/players/{id}/stats — получить статистику конкретного игрока;

POST /api/v1/player-stats — создать запись статистики игрока;

PATCH /api/v1/player-stats/{id} — обновить статистику игрока;

DELETE /api/v1/player-stats/{id} — удалить запись статистики.



Пример ресурса PlayerStat:

{

&#x20; "statId": 1,

&#x20; "playerId": 1,

&#x20; "goals": 25,

&#x20; "assists": 2

}



Аналитика

1. GET /api/v1/statistics/total-goals — получить общее количество голов;

5. Схемы запросов и ответов:

Создание игрока

POST /api/v1/players

Запрос:

json

{

&#x20; "playerName": "Криштиану Роналду",

&#x20; "nationality": "Португалия",

&#x20; "teamId": 1

}

Ответ:

{

&#x20; "playerId": 1,

&#x20; "playerName": "Криштиану Роналду",

&#x20; "nationality": "Португалия",

&#x20; "teamId": 1

}

Статус ответа: 201 Created.



Получение статистики игрока

GET /api/v1/players/1/stats

Ответ:

{

&#x20; "playerId": 1,

&#x20; "playerName": "Криштиану Роналду",

&#x20; "goals": 25,

&#x20; "assists": 2

}

Статус ответа: 200 OK.



Ошибка, если игрок не найден

GET /api/v1/players/999

Ответ:

{

&#x20; "error": "PlayerNotFound",

&#x20; "message": "Игрок с указанным id не найден"

}

Статус ответа: 404 Not Found.



6\. Обязательные поля:

1. "League": "leagueName";
2. "Team": "teamName", "leagueId";
3. "Player": "playerName", "teamId";
4. "PlayerStat": "playerId".



Доп.правила:

1. "goals", "assists", "points", "matchesPlayed", "goalsFor", "goalsAgainst" не могут быть отрицательными;
2. \- "leagueId", "teamId", "playerId" должны ссылаться на существующие записи;
3. \- названия лиги, команды и имя игрока не должны быть пустыми строками.



1. Статус-коды ошибок:
2. 200 OK — запрос успешно выполнен;
3. 201 Created — новая запись успешно создана;
4. 400 Bad Request — в запросе переданы некорректные данные;
5. 401 Unauthorized — пользователь не авторизован;
6. 403 Forbidden — у пользователя нет прав на выполнение действия;
7. 404 Not Found — ресурс с указанным ID не найден;
8. 409 Conflict — конфликт данных, например попытка удалить лигу, к которой привязаны команды;
9. 429 Too Many Requests — превышен лимит запросов;
10. 500 Internal Server Error — внутренняя ошибка сервера.



8\. Правила безопасности

Для защищённых endpoint-ов используется авторизация через токен.

Пример заголовка:

http

Authorization: Bearer <token>



В API предусмотрены роли пользователей:

1. viewer — может просматривать данные;
2. editor — может добавлять и обновлять данные;
3. admin — может удалять данные.

Правила доступа:

1. GET-запросы доступны авторизованным пользователям;
2. POST и PATCH доступны ролям editor и admin;
3. DELETE доступен только роли admin.

Также:

1. Проверка входных данных;
2. Ограничение запросов: 100 запросов в минуту на пользователя;
3. Передача данных только по HTTPS.

При развитии API нужно соблюдать совместимость:

1. Не удалять существующие endpoints без предупреждения;
2. Не менять структуру ответов без необходимости;
3. Новые поля добавлять так, чтобы старые клиенты продолжали работать.
